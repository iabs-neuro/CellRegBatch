# CellRegBatch: справочник

Справочник описывает батч-слой CellRegBatch: что делает код, шаг за шагом, и
каждый файл и каждое число, которые он записывает. Для первого запуска
прочитайте [руководство](GUIDE_ru.md). English version: [MANUAL.md](MANUAL.md).

CellRegBatch не меняет метод регистрации. Метод — CellReg (Sheintuch et al.,
2017, *Cell Reports* 21:1102–1115,
[doi:10.1016/j.celrep.2017.10.013](https://doi.org/10.1016/j.celrep.2017.10.013)).
Сам метод описан в этой статье и в
[CellReg User Manual](User%20Manual.docx).

**Термины**

| Термин | Значение |
|---|---|
| сессия | Одна сессия записи. Один входной `.mat` файл. |
| датасет | Все сессии одного животного в одном эксперименте, например `CC_H02`. Батч регистрирует каждый датасет отдельно. |
| батч | Все датасеты в одной входной папке. |
| референсная сессия | Сессия, к которой выравниваются остальные. |
| зарегистрированная клетка | Одна строка `cell_to_index_map` CellReg: одна клетка, прослеженная по сессиям. |
| карта клеток | `cell_to_index_map`: строки — клетки, столбцы — сессии, значение — номер клетки в файле сессии, 0 — клетки в этой сессии нет. |
| варнинг | Предупреждение о качестве датасета: нет, жёлтый или красный. |

## 1. Входные файлы

### 1.1 Содержимое файла

Каждая сессия — один `.mat` файл. Батч загружает **первую переменную**
файла. Эта переменная — трёхмерный массив пространственных фильтров (spatial
footprints) размера N×Y×X: N клеток, Y пикселей по высоте, X пикселей по
ширине. Это входной формат CellReg (см. `CellReg/load_single_session.m`).
Подходит любой числовой тип. Батч переводит его в `double`.

Для перевода выходов других программ в этот формат используйте конвертеры
CellReg в папке `Helper/`: `format_conversion_Suite2p_CNMF_e.m`,
`format_conversion_inscopix.m`, `s2pToCellReg.m`.

### 1.2 Имена файлов

Батч берёт эксперимент, животное и сессию из имени файла. Имя должно
подходить под регулярное выражение:

```
^([A-Za-z0-9]+)_([A-Za-z]{1,2}\d{2})_(\dD|\dT)(_\dT)?.*\.mat$
```

| Часть | Правило | Примеры |
|---|---|---|
| Эксперимент | Латинские буквы и цифры. Без подчёркивания. | `CC`, `HOS`, `BOWL2` |
| Животное | 1 или 2 латинские буквы, затем ровно 2 цифры. | `H02`, `F54`, `JA07` |
| Сессия | 1 цифра, затем `D` (день) или `T` (проба). Может идти вторая часть `_<цифра>T`. | `1D`, `5D`, `2T`, `1D_2T` |
| Остаток | Любой текст перед `.mat`. Батч его не учитывает. | `_filters`, `_converted` |

| Имя файла | Результат |
|---|---|
| `CC_H02_1D.mat` | датасет `CC_H02`, сессия `1D` |
| `CC_H02_3D_filters.mat` | датасет `CC_H02`, сессия `3D` |
| `NOF_F07_1D_2T_cnmf.mat` | датасет `NOF_F07`, сессия `1D_2T` |
| `CC_H2_1D.mat` | не распознан: у животного должно быть 2 цифры |
| `CC_H02_10D.mat` | не распознан: у сессии только 1 цифра |
| `CC-H02-1D.mat` | не распознан: разделитель должен быть `_` |

Батч читает только файлы в самой входной папке, без подпапок. Файлы с
неподходящими именами он пропускает. GUI показывает их число (**Unparsed
files**).

### 1.3 Порядок сессий и референсная сессия

Батч сортирует файлы датасета по полному имени файла, по алфавиту. Это и есть
порядок сессий. Сессия 1 — первый файл. Например: `1D` < `1D_2T` < `1T` <
`2D`.

Референсная сессия — сессия с номером `reference_session_index` в этом порядке
(по умолчанию 1, первая сессия).

### 1.4 Датасеты, которые пропускаются

Скан отмечает датасет как пропускаемый, если:

- у него меньше 2 сессий;
- два файла дают одну и ту же сессию (например `CC_H02_1D_a.mat` и
  `CC_H02_1D_b.mat`).

У пропускаемого датасета в таблице GUI снята галочка **Run**. Причина записана
в лог батча.

### 1.5 Пропущенные сессии

Задайте в `expected_n_sessions` число сессий вашего эксперимента. Датасет с
другим числом сессий **не** пропускается. Батч метчит те сессии, что у него
есть, и ставит ему красный варнинг `session_count`.

Названия сессий батча — все названия сессий, найденные в папке (пропускаемые
датасеты не считаются). Они задают столбцы каждой карты клеток (5.6).
Например, в батче есть `1D`–`5D`, а у мыши `F07` нет `3D`. Тогда в карте
клеток `F07` 5 столбцов, и столбец 3 целиком из нулей. У всех карт батча
одинаковые столбцы.

Батч записывает названия сессий в лог (`cell map columns`). Если их число не
равно `expected_n_sessions`, в логе появляется строка `WARN`: проверьте имена
файлов.

## 2. Запуск батча

### 2.1 GUI

Запустите GUI из папки репозитория:

```matlab
run BatchCellReg_GUI/BatchCellReg.m
```

текущую сессию. Путь он не сохраняет.

### 2.2 Скрипт

Чтобы запустить батч без GUI, используйте `batch_run`:

```matlab
addpath(genpath('CellReg')); addpath(genpath('Helper')); addpath(genpath('BatchCellReg'));

cfg = batch_default_config();             % или: cfg = config_from_json('my_config.json');
cfg.cellreg.microns_per_pixel = 1.6;      % задайте для своего микроскопа
summary = batch_run('D:\data\5_Filters', cfg);

% Запустить только некоторые датасеты:
opts = struct('selected_datasets', {{'CC_H02', 'CC_H03'}});
summary = batch_run('D:\data\5_Filters', cfg, opts);
```

`batch_run(input_folder, cfg, opts)` берёт папку из аргумента
`input_folder`. Поле `cfg.io.input_folder` он не читает.

| Поле `opts` | Значение |
|---|---|
| `selected_datasets` | Cell-массив имён датасетов для запуска. Если поля нет, запускаются все датасеты, кроме пропускаемых. Пустой cell-массив не запускает ни одного. |
| `live_log_callback` | Указатель на функцию `@(line)`. Получает каждую строку лога. |
| `stop_check` | Указатель на функцию; вернёт `true` — батч остановится перед следующим датасетом. |

| Поле `summary` | Значение |
|---|---|
| `results` | Массив структур, один элемент на обработанный датасет (см. 4.8). |
| `anomalies` | `.flags` (шесть варнингов на датасет: 0 — нет, 1 — жёлтый, 2 — красный), `.metrics` (значения за ними), `.details` (по элементу на сработавшее правило, строки из 5.2), `.batch` (медиана и пороги сравнения с батчем). |
| `output_dir`, `log_file`, `results_csv`, `detail_csv`, `match_stats_csv`, `warnings_png` | Пути к выходной папке и файлам. `warnings_png` пустой, если картинка не построилась. |
| `n_succeeded`, `n_failed`, `n_with_warnings` | Счётчики. Датасет считается «с варнингами», если хотя бы один варнинг жёлтый или красный. |
| `stopped` | `true`, если батч остановили раньше. |

## 3. Параметры

Конфиг — структура MATLAB. Значения по умолчанию задаёт
`batch_default_config.m`. `config_to_json` и `config_from_json` сохраняют и
загружают его как JSON. Каждый прогон сохраняет свой конфиг как
`_batch_config.json` в выходной папке.

Чтобы изменить параметр, которого нет в GUI:

1. Нажмите **Save config as...** и сохраните JSON файл.
2. Откройте файл в текстовом редакторе и измените значение.
3. Нажмите **Load config...** и выберите этот файл.

| Параметр | GUI | По умолчанию | Значение |
|---|---|---|---|
| `cellreg.microns_per_pixel` | да | 1.6 | Размер пикселя ваших изображений в мкм. **Задайте для своего микроскопа.** От него зависят все расстояния и модель. |
| `cellreg.alignment_type` | да | `Translations` | Первый режим каскада выравнивания (4.3). `Translations and Rotations` начинает со второго режима. `Non-rigid` использует только последний режим. |
| `cellreg.maximal_rotation` | да | 5 | Диапазон поворота в градусах для второго режима каскада. |
| `cellreg.reference_session_index` | да | 1 | Номер референсной сессии в порядке сессий (1.3). |
| `cellreg.maximal_distance_um` | да | 15 | «Maximal distance» CellReg: пары клеток с центроидами дальше этого расстояния не сравниваются. В `demo.m` CellReg — 14. На наших данных большое значение (50) ломало модель пространственной корреляции на плотных полях зрения. |
| `cellreg.registration_approach` | заблокирован | `Probabilistic` | Не используется. Батч всегда использует вероятностный подход (4.4). |
| `cellreg.initial_registration_type` | да (**Registration model**) | `auto` | `auto`: CellReg выбирает модель, которая лучше подходит. `Spatial correlation` или `Centroid distance`: эта модель для всех датасетов (4.4). |
| `cellreg.use_parallel_processing` | да | `true` | `parfor` при выравнивании в CellReg. Нужен Parallel Computing Toolbox. Без тулбокса выключите. |
| `cellreg.figures_visibility` | да | `off` | `on` показывает каждый рисунок CellReg во время батча. Рисунки сохраняются в обоих случаях. |
| `cellreg.write_to_file` | да | `true` | Записывать `cellRegistered_*.mat`, `logFile_*.txt` и карту клеток каждого датасета. Рисунки и таблицы батча пишутся в обоих случаях. |
| `cellreg.alignment_min_xcorr` | да (**Alignment gate**) | 0.2 | Критерий прохождения режима выравнивания (4.3). |
| `cellreg.expected_n_sessions` | вкладка Setup | 5 | Ожидаемое число сессий на датасет (1.5). **Задайте для своего эксперимента.** |
| `cellreg.rotation_fallback_deg` | JSON | 90 | Диапазон поворота в градусах для третьего режима каскада. |
| `cellreg.nonrigid_smoothness` | JSON | 2 | Гладкость для нежёсткого режима. CellReg передаёт её в `imregdemons` как `AccumulatedFieldSmoothing`. |
| `p_same_tuning.fpr_max` | да | 0.03 | Целевая доля ложноположительных (FPR) для порога P_same (4.5). |
| `anomaly_thresholds.few_cells_yellow`, `few_cells_red` | да | 60, 30 | `few_cells`: медиана клеток за сессию ниже порога. |
| `anomaly_thresholds.cell_drop_yellow`, `cell_drop_red` | да | 0.6, 0.4 | `cell_drop`: клетки худшей сессии ÷ медианная сессия ниже порога. |
| `anomaly_thresholds.xcorr_yellow`, `xcorr_red` | да | 0.3, 0.25 | `alignment`: наименьшая кросс-корреляция ниже порога. |
| `anomaly_thresholds.shift_yellow_px` | да | 30 | `alignment`: наибольший сдвиг выше порога, в пикселях. Только жёлтый. |
| `anomaly_thresholds.mse_yellow`, `mse_red` | да | 0.1, 0.15 | `model_fit`: ошибка модели (MSE) выше порога. |
| `anomaly_thresholds.match_z_yellow`, `match_z_red` | да | 2, 3 | `low_match`: процент метчинга ниже медианы батча больше чем на столько робастных стандартных отклонений. |
| `anomaly_thresholds.session_link_yellow`, `session_link_red` | да | 0.6, 0.4 | `low_match`: связность сессий (раздел 6) ниже порога. |
| `io.input_folder` | да | пусто | Папка, выбранная в GUI. `batch_run` её не читает. |
| `io.output_subfolder_name` | JSON | `Matching` | Выходная папка относительно входной. Можно путь вида `..\6_Matched`. |
| `version` | – | 2 | Версия формата конфига. `config_from_json` читает версии 1 и 2, другие отклоняет. |

Некоторые значения зашиты в код:

| Значение | Где | Почему |
|---|---|---|
| `sufficient_correlation_footprints` = 0.2 и `sufficient_correlation_centroids` = 0.2 | `run_single_dataset.m` | Те же значения, что в GUI CellReg (`GUI/CellReg.m`). В `demo.m` CellReg для фильтров 0.3. С 0.3 CellReg отвергал жёсткое выравнивание сессий, которые GUI CellReg выравнивает. |
| Уровень уверенности P_same = 0.95 | `run_single_dataset.m` | CellReg по нему оценивает долю неопределённых пар клеток, как в `demo.m`. |
| Наименьший батч для сравнения процента метчинга = 5 датасетов | `detect_anomalies.m` | Медиана и MAD меньшего числа значений неустойчивы. |

### 3.1 Файлы конфига старой версии

`config_from_json` начинает со значений по умолчанию и берёт каждое значение,
которое есть в файле. Поэтому файл без новых полей всё равно загружается. В
файлах версии 1 три порога варнингов назывались иначе. Они загружаются под
новыми именами:

| Имя в версии 1 | Новое имя |
|---|---|
| `min_xcorr` | `xcorr_yellow` |
| `max_mse` | `mse_yellow` |
| `max_translation_px` | `shift_yellow_px` |

У `z_threshold` нового имени нет, он не учитывается. Поле, которого эта версия
не знает, вызывает предупреждение MATLAB и не учитывается.

## 4. Что происходит с каждым датасетом

Батч обрабатывает датасеты по очереди. Если датасет падает с ошибкой, батч
записывает ошибку и переходит к следующему. Все шаги ниже — в
`BatchCellReg/run_single_dataset.m`. Кроме 4.3 и 4.5, каждый шаг вызывает те же
функции CellReg, что `CellReg/demo.m`.

### 4.1 Загрузка

`prepare_session_files` загружает первую переменную каждого файла (1.1).

### 4.2 Подготовка фильтров (этап 1 CellReg)

CellReg нормирует фильтры, дополняет все сессии до одного поля зрения и
считает проекции и центроиды.

### 4.3 Выравнивание сессий (этап 2 CellReg) с каскадом режимов

Батч вызывает `align_images` CellReg с режимами в таком порядке (до четырёх):

| Режим | Тип выравнивания CellReg | Параметр |
|---|---|---|
| 1 | `Translations` | – |
| 2 | `Translations and Rotations` | `maximal_rotation` (5°) |
| 3 | `Translations and Rotations` | `rotation_fallback_deg` (90°) |
| 4 | `Non-rigid` | `nonrigid_smoothness` (2) |

Каскад начинается с режима, заданного `alignment_type`. Режим **проходит**,
если верно и то, и другое:

- после выравнивания ни одна сессия, кроме референсной, не пустая;
- у каждой нереференсной сессии максимальная кросс-корреляция с референсной не
  меньше `alignment_min_xcorr` (0.2).

Батч берёт первый прошедший режим. Если режим не прошёл или упал с ошибкой,
батч пробует следующий.

Если не прошёл ни один режим, возможны два случая:

- Хотя бы один режим не оставил пустых сессий. Батч берёт режим с наибольшей
  минимальной кросс-корреляцией и продолжает. Лог и результат помечают этот
  режим как `(forced, low xcorr=...)`. Варнинг `alignment` тогда красный.
- Каждый режим оставил пустую сессию. Датасет падает с ошибкой
  `All alignment modes failed ...`.

### 4.4 Модель сходства пар клеток (этап 3 CellReg)

CellReg строит распределения расстояний между центроидами и пространственных
корреляций для соседних пар клеток. Для каждого распределения он подгоняет
модель пар «та же клетка» и «разные клетки» и оценивает точность регистрации.

При **Registration model** = `auto` функция `choose_best_model` CellReg
выбирает модель расстояний между центроидами или модель пространственной
корреляции. Она берёт модель с меньшей суммой ложноположительных,
ложноотрицательных и ошибки модели (MSE). См. также замечание о
`choose_best_model` в разделе 9. При `Spatial correlation` или
`Centroid distance` батч использует эту модель для всех датасетов. Тогда в
логе есть строка `model ... set in config (best fit: ...)`.

Батч всегда использует вероятностный подход, поэтому поле **Registration
approach** в GUI заблокировано.

### 4.5 Выбор порога P_same (батч-слой)

P_same — вероятность того, что две клетки из разных сессий — одна и та же
клетка. CellReg регистрирует пару, если P_same выше порога. Порог CellReg по
умолчанию — 0.5. Батч выбирает порог по правилу:

1. Посчитать долю ложноположительных (FPR) при P_same = 0.5.
2. Если FPR ≤ `fpr_max` (0.03), взять 0.5.
3. Если нет, повышать порог шагом 0.001 до 0.95. Взять первый порог с
   FPR ≤ `fpr_max`.
4. Если ни один порог до 0.95 не даёт FPR ≤ `fpr_max`, взять 0.95. Варнинг
   `model_fit` тогда красный.

FPR — то значение, которое CellReg пишет в `logFile_*.txt` как «Fraction of
false positives». Батч считает его так же, как `CellReg/save_log_file.m`:
накопленная доля ложноположительных выбранной модели при пороге, округлённом
до 2 знаков. Батч хранит значение без последнего округления до 0.01 (столбец
`chosen_fpr_pct`, в процентах).

Код — в `BatchCellReg/choose_p_same_by_fpr.m`.

### 4.6 Начальная регистрация (этап 4 CellReg)

CellReg делает начальную регистрацию выбранной моделью. Порог — точка
пересечения распределений «та же клетка» и «разные клетки». Если CellReg не
находит пересечения, батч берёт значения из `demo.m`: 0.65 для
пространственной корреляции, 5 мкм для расстояния между центроидами.

### 4.7 Окончательная регистрация (этап 5 CellReg)

CellReg кластеризует клетки вероятностным подходом с порогом P_same из 4.5.
Получаются окончательная `cell_to_index_map` и оценки клеток (cell scores).

### 4.8 Сохранение

При включённом `write_to_file` батч сначала удаляет старые
`cellRegistered_*.mat` и `logFile_*.txt` в папке датасета. Затем пишет новые.
В каждой папке датасета один результат. Батч также пишет карту клеток
датасета как `<датасет>_cellmap.csv` в выходную папку (5.6). В карте клеток по
одному столбцу на каждое название сессии батча (1.5).

Результат, который батч хранит для варнингов, имеет поля: `dataset_id`,
`sessions`, `missing_sessions`, `n_cells_per_session`, `match_stats`,
`maximal_cross_correlation`, `alignment_translations`, `alignment_shift_px`,
`reference_session_index`, `MSE_model`, `best_model_string`, `chosen_p_same`,
`chosen_fpr`, `p_same_unreachable`, `alignment_mode`, `forced_low_xcorr`,
`error`. `match_stats(1)` — число зарегистрированных клеток.
`match_stats(k+1)` — число зарегистрированных клеток, найденных ровно в S−k+1
из S сессий, то есть `match_stats(2)` — число найденных во всех сессиях.

Батч закрывает все рисунки, которые открыл, в том числе после ошибки. Иначе
скрытые рисунки заполняют память за долгий батч.

пропущенный рисунок и полный отчёт об ошибке упавшего датасета.

## 6. Варнинги

После всех датасетов `detect_anomalies.m` ставит каждому неупавшему датасету
шесть варнингов. Каждый варнинг — нет, жёлтый или красный. Варнинг берёт
худший уровень из своих правил.

- **Жёлтый:** посмотрите на датасет, если есть время.
- **Красный:** посмотрите на датасет, прежде чем его использовать.

| Варнинг | Заголовок в GUI | Жёлтый | Красный | Что это может значить |
|---|---|---|---|---|
| `session_count` | Sessions | – | Число сессий ≠ `expected_n_sessions`. | Файл сессии пропущен или лишний. Датасет сметчен; в его карте клеток нулевые столбцы на месте пропущенных сессий (1.5). |
| `few_cells` | Few cells | Медиана клеток за сессию < 60. | < 30. | С малым числом клеток модель и статистика менее надёжны. У таких датасетов часто бывают и варнинги `model_fit` и `alignment`. |
| `cell_drop` | Cell drop | Клетки худшей сессии ÷ медианная сессия < 0.6. | < 0.4. | Одна сессия потеряла много клеток: проверьте её запись и курацию. Столбец `session` называет её. |
| `alignment` | Alignment | Наименьшая кросс-корреляция с референсной < 0.3 или наибольший сдвиг > 30 px. | Наименьшая кросс-корреляция < 0.25 или ни один режим выравнивания не прошёл (4.3). | Сессия не похожа на референсную. Посмотрите `Stage 2 - pre vs post alignment`. Большой сдвиг может быть верным, но перекрывается меньшая часть поля зрения. |
| `model_fit` | Model fit | Ошибка модели (MSE) > 0.1. | MSE > 0.15 или ни один P_same до 0.95 не даёт `fpr_max` (4.5). | Модель плохо описывает данные. Посмотрите `Stage 3 - model`. У датасетов с малым числом клеток MSE бывает высокой из-за шума гистограммы, хотя подгонка выглядит хорошо. |
| `low_match` | Low match | Связность сессий < 0.6, или процент метчинга ниже медианы батча больше чем на 2 робастных SD. | Ни одной клетки во всех сессиях, или связность сессий < 0.4, или процент метчинга ниже медианы батча больше чем на 3 робастных SD. | Мало клеток прослежено через все сессии. Низкая связность указывает на одну сессию (её называет столбец `session`): обычно она плохо выровнена или показывает другое поле зрения. Другие причины: плохая сессия, плохое выравнивание или реальное различие. |

Все пороги — параметры конфига (раздел 3). В таблице — значения по умолчанию.

**Связность сессий.** Для каждой сессии батч берёт долю её клеток, найденных
хотя бы в одной другой сессии. Связность — доля худшей сессии ÷ медианная доля
датасета. В хороших датасетах сессии связаны примерно одинаково (0,6–1).
Сессия, которая не перекрывается с остальными (неверное выравнивание, другое
поле зрения), даёт связность около 0. Правило сравнивает сессии одного
датасета, поэтому работает в батче любого размера. Нужно 3 сессии или больше:
при 2 сессиях связанные клетки у них общие.

**Процент метчинга и сравнение с батчем.** Процент метчинга — определение
лаборатории: клетки, найденные во всех сессиях ÷ среднее число клеток за
сессию (`pct_in_all_of_mean`). Батч сравнивает его с медианой батча:

- робастное SD = MAD ÷ 0.6745, где MAD — медиана |процент − медиана|;
- робастный z = (процент − медиана) ÷ робастное SD.

Медиана и MAD мало меняются от одного плохого датасета. Поэтому плохой датасет
не может спрятаться, как со средним и SD. В сравнение входят только датасеты с
`expected_n_sessions` сессиями: у датасета с меньшим числом сессий клеток «во
всех сессиях» больше по построению. Нужно не меньше 5 таких датасетов, и
большинство из них должно быть хорошими. Если их меньше, работают только два
других правила `low_match`.

**Откуда эти пороги.** Мы проверили правила на 83 датасетах, которые лаборатория
сметчила раньше (октябрь 2026): HOS 42 мыши × 5 сессий, HOS-J 13 × 4, LNOF
22 × 4, LT1 6 × 4. Красные флаги получили HOS D01, D04, D11 и J21 (четыре мыши,
которых лаборатория исключила), HOS D17 (в сессии 1 118 клеток, в остальных
около 400), HOS F11 (29 клеток за сессию) и LT1 K02, K08 и K09 (мало клеток;
у K08 к тому же не прошло выравнивание). LNOF и HOS-J красных флагов не
получили. Старые правила (версия 1) отмечали 38 из 83 датасетов, новые — 19.
Связность ниже 0,4 была только у HOS D01 (сессия 5: 0,15). У хороших датасетов
она была 0,62 и выше.

Код — в `BatchCellReg/detect_anomalies.m`. Тексты поля расшифровки — в
`BatchCellReg/anomaly_decode_map.m`, тексты кнопок **?** — в
`BatchCellReg/parameter_info.m`.

## 7. Как использовать результаты

### 7.1 Загрузка регистрации

Батч сохраняет структуру результата CellReg как `cell_registered_struct`, с
тем же именем и полями, что у GUI CellReg и `demo.m`. Код, написанный для
результатов CellReg, читает результаты батча без изменений.

```matlab
f = dir(fullfile(out_dir, 'CC_H02', 'cellRegistered_*.mat'));
s = load(fullfile(f(1).folder, f(1).name));
map = s.cell_registered_struct.cell_to_index_map;   % клетки x сессии
```

Вне MATLAB используйте `CC_H02_cellmap.csv` в выходной папке. В нём та же
карта, с нулевым столбцом на каждую пропущенную сессию (1.5).

`map(i, j)` — номер зарегистрированной клетки `i` в сессии `j`, в порядке
входных фильтров. 0 значит, что в этой сессии клетка не найдена. Остальные
поля (`cell_scores`, `p_same_registered_pairs`,
`spatial_footprints_corrected` и другие) описаны в CellReg User Manual.

### 7.2 Процент клеток, найденных во всех сессиях

`pct_in_all` делит клетки, найденные во всех сессиях, на число
зарегистрированных клеток. `pct_in_all_of_mean` делит их на среднее число
клеток за сессию. Второе значение больше. Это «процент метчинга» лаборатории и
**Match %** в GUI. `_batch_results.csv` и `_match_statistics.csv` дают оба, в
процентах. Чтобы посчитать их по карте:

```matlab
in_all      = sum(all(map > 0, 2));
per_session = sum(map > 0, 1);
pct_in_all         = 100 * in_all / size(map, 1);
pct_in_all_of_mean = 100 * in_all / mean(per_session);
```

Берите здесь карту из `.mat` файла. В CSV карте нулевой столбец пропущенной
сессии сделал бы `all(map > 0, 2)` нулём для каждой клетки.

Укажите в методах, какое определение вы используете.

## 8. Тесты

Тесты написаны на фреймворке unit-тестов MATLAB. Запустите их из папки
репозитория:

```matlab
results = runtests('tests/BatchCellReg');
```

или запустите `tests/BatchCellReg/runAllTests.m`. Он завершается с ошибкой,
если какой-то тест не прошёл.

- Unit-тесты используют маленькие синтетические данные. Они идут несколько
  секунд.
- `test_runs_on_shipped_cellreg_sample_data` прогоняет полный батч на
  `SampleData/` (5 сессий одной мыши) и на копии той же мыши без сессии `3D`
  (1.5). Это 4–5 минут.
- `test_model_can_be_set_in_config` прогоняет 2 сессии с моделью расстояний
  между центроидами, заданной в конфиге.
- `test_runs_on_sample_data_our` нужна папка `SampleDataOur/` с нашими
  данными. Этой папки нет в репозитории, поэтому тест получает статус
  *Incomplete*. Так и должно быть.

GitHub Actions запускает все тесты на каждый push в `main` и на каждый pull
request (`.github/workflows/tests.yml`): последний MATLAB на Linux, Windows и
macOS и MATLAB R2021a на Linux. GUI там не тестируется.

## 9. Известные ограничения

- **Имена.** ID животного — 1–2 буквы и ровно 2 цифры. Номер сессии — одна
  цифра, поэтому у датасета не больше 9 дневных сессий (`1D`–`9D`).
- **Фиксированный подход.** Подход регистрации всегда вероятностный. Модель
  выбрать можно (4.4), подход простого порога — нет. Если он нужен,
  используйте GUI CellReg (`GUI/CellReg.m`) для одного датасета.
- **Порядок сессий.** Батч сортирует сессии по имени файла (1.3). Чтобы
  изменить порядок, переименуйте файлы.
- **Выбор модели в CellReg v1.6.0.** В `CellReg/choose_best_model.m` строки
  28–29 считают ложноположительные и ложноотрицательные модели расстояний
  между центроидами в точке `ind_05_correlation` (индекс модели
  пространственной корреляции). Строка 27 считает `ind_05_distance`, но код
  его не использует. Поэтому выбор между моделями (4.4) может быть
  неточным. Этот файл CellReg мы не меняли.
- **Рисунки.** В `.mat` результате нет данных модели, поэтому рисунки по нему
  не восстановить. Чтобы получить их, прогоните датасет заново.
- **Операционная система.** Тесты идут на Linux, Windows и macOS (раздел 8).
  GUI мы проверяли только под Windows.
